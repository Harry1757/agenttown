# ClaudeTown

Claude Code 가 지금 무슨 작업을 하는지 도트 맵으로 본다.

`~/.claude/projects/*/*.jsonl` 을 읽는다. 훅도, 설정도, 의존성도 없다.
서버는 `127.0.0.1` 에만 바인드하고, 브라우저로 나가는 것은 툴 이름, 최대 40자로
자른 라벨(명령어 앞부분이나 파일 경로), 프로젝트 슬러그, 세션 제목뿐이다 — 파일
본문·프롬프트·툴 결과는 절대 담기지 않는다.

## 실행하는 세 가지 방법

**1. 그냥 서버만.** 의존성 없음.

    python3 claudetown.py  # 브라우저가 열린다

**2. 키오스크 런처.** 의존성 없음(WSL). 서버를 띄우고 Chrome 을 `--app`
모드(주소창·탭·북마크바 없음)로 연다. 이미 떠 있으면 새로 안 띄운다.

    ./launch.sh            # 서버 확인/시작 + 브라우저를 앱모드로
    ./launch.sh --stop      # 이 스크립트가 띄운 서버만 종료

Windows 쪽에서 더블클릭하려면 `ClaudeTown.bat`(또는 콘솔 창이 아예 안 뜨는
`ClaudeTown.vbs`)를 쓴다. 둘 다 내부적으로 `wsl.exe` 로 `launch.sh` 를 부른다 -
저장소를 `~/projects/claudetown` 이 아닌 곳에 두었다면 `ClaudeTown.vbs` 안의
경로를 고쳐야 한다.

**3. Electron 앱.** 진짜 창·트레이·시작 메뉴 고정이 되는 데스크톱 앱.
Chrome 앱모드로 고정하면 작업표시줄에 "Chrome"으로 잡히는 문제가 있어서 만들었다.
Windows 쪽 Node/npm 이 필요하다(`app/` 안에서만 - 저장소 나머지는 여전히
의존성이 없다).

    cd app
    npm install
    npm run install-app    # 정식 설치: %LOCALAPPDATA%\ClaudeTown 에 복사 + 바로가기
    npm run uninstall-app  # 되돌리기(바로가기 + 복사본 삭제)

`npm run install-app` 이 진짜 설치 단계다 - Electron 셸을 Windows 로컬
경로(`%LOCALAPPDATA%\ClaudeTown`)로 복사하고 그 복사본에서 다시
`npm install` 한 뒤, 시작 메뉴/자동 실행 바로가기를 그 복사본으로 건다.
`electron.exe` 를 저장소가 있는 `\\wsl.localhost\...` 경로에서 그대로
돌리면 Chromium 의 OS 샌드박스가 GPU/네트워크 자식 프로세스를 못 띄운다 -
그래서 셸만 로컬로 옮긴다. 파이썬 서버는 계속 WSL 에 있다(`~/.claude/projects`
를 읽는 게 그거니까).

    npm start   # 저장소(WSL 경로)에서 바로 띄우기 - 개발용 편의 명령

`npm start` 는 저장소 안에서 바로 띄우는 개발 편의 명령이다(UNC 경로라서
OS 샌드박스를 개발 중에만 끈다 - `src/main.js` 의 ponytail 주석 참고).
실제로 쓸 때는 `install-app` 으로 설치한 쪽을 쓴다.

트레이 메뉴: 열기 / 항상 위 / 종료. 창을 닫아도(X) 종료가 아니라 트레이로
숨는다 - 종료는 트레이 메뉴에서만, 이때 WSL 쪽 서버도 같이 내린다.
아이콘을 다시 그리려면 `python3 app/tools/draw-icon.py && npm run icon`
(`app/` 안에서, 그 다음 `install-app` 을 다시 돌려야 설치본에도 반영된다).

- 방 12개, 4열x3행. 위에서부터 일이 흘러가는 순서다 —
  `기획·리서치·디자인·회의` / `탐색·프론트·백엔드·인프라` / `QA·릴리즈` +
  마지막 두 칸이 **상태 구역**(`응답 대기`·`완료`).
  일하는 중이면 그 작업의 업무 구역에, 아니면 상태 구역에 선다.
- `응답 대기` 방은 사람이 있으면 불이 켜진다. 화면을 흘깃 봤을 때 "내 차례인
  세션이 있나"만 보면 되게 하려는 것이다.
- 세션마다 캐릭터 하나. 지금 하는 작업에 맞는 방에 가서 선다 — 작업이 바뀌면
  방을 옮긴다. 앱을 켤 때 과거 세션도 마지막으로 있던 방에 세운다(어느 방이었는지
  못 찾으면 세우지 않는다 — 아무 방에나 놓지 않는다).
- 상태 셋: **작업 중**(초록, 턴 진행 중) / **응답 대기**(노랑, 턴이 끝나 내 차례) /
  **완료**(회색, 30분 넘게 조용함). 가르는 기준은 시간이 아니라 '턴이 끝났나' 다. 명찰 점 색과 밝기, 하단 줄, 툴팁에 같이 나온다. `완료` 는
  추측이다 — Claude Code 가 세션 종료를 기록하지 않아 방치 시간으로 가른다
  (`DONE_AFTER`). 이틀(`HIDE_AFTER`) 넘게 조용한 세션은 아예 안 나온다 —
  완료 방이 몇 달치로 차면 "오늘 뭐가 끝났나"를 못 읽는다.
- 명찰 = **세션 제목** · 프로젝트. 제목을 앞에 둔다 — 한 저장소에서 여러 세션을
  돌리면 프로젝트 이름이 전부 같아서 누가 누구인지 못 가른다. 방이 붐비면
  (둘 이상) 제목만 남기고, 다섯을 넘으면 글자를 버리고 상태 점만 남는다.
  전체 정보는 호버 툴팁에 그대로 있다.
- **캐릭터 크기 = 그 세션이 쓴 토큰량** (최대 2배까지). 실측 분포가 5만~4천만이라
  로그로 매핑한다. 배율은 줌과 같은 격자(`ZOOM_STEP`)에 맞춘다 — TILE 이 16 이라 0.25 배수는
  타일이 항상 정수 픽셀이라 경계가 안 깨진다.
- 캐릭터 생김새는 세션마다 다르다(시트에서 사람으로 읽히는 14칸 중 키 해시로 고정).
  서브에이전트만 슬라임으로 고정.
- 상태와 **방마다** 동작이 다르다(`IDLE` 표). 기획은 `…` 를 띄우며 고민하고,
  탐색은 두리번거리고, QA 는 빠르게 끄덕이고, 릴리즈는 가끔 폴짝 뛴다.
  회의는 서로 마주보고 끄덕인다. 응답 대기는 사람을 찾듯 두리번거리고, 완료는
  숨쉬기까지 멈춘다.
- **표정은 이모지로 낸다.** 방마다 다르고(📝 기획 · 🔍 탐색 · 🧪 QA · 🚀 릴리즈 …),
  그 위에 상황이 얹힌다 — 최근 30초에 툴을 6번 넘게 쓰면 🔥, 45초 넘게 조용하면
  🤔, 응답 대기는 👀, 완료는 😴. 툴 결과는 안 받으므로 성공·실패는 알 수 없고
  리듬만 안다.
- 방 이름표는 방 안이 아니라 아래 출입구에 걸린다.
- 방 안 가구는 전부 코드로 그린다(Kenney 시트는 캐릭터에만 쓴다). 책상·모니터·
  의자·러그에 더해 왼쪽 벽에 방 성격에 맞는 수납이 선다 — 백엔드·인프라는 서버
  랙(LED 가 이벤트에 맞춰 밝아진다), 회의·응답 대기는 정수기, 리서치·디자인은
  선반, 나머지는 서랍장. 오른쪽 아래 구석엔 휴지통.
- 작업 중인 방은 모니터가 켜져 있다.
- 조작: 휠로 확대·축소(커서 기준, 0.25 단계 — `ZOOM_STEP`), 드래그로 이동,
  더블클릭으로 리셋, `+`/`-`/`0`/방향키, 호버하면 툴팁.
- **제스처**: 오른쪽 아래 버튼(쓰다듬기 / 때리기)을 켜고 캐릭터를 클릭한다.
  켜져 있는 동안에는 캐릭터 위 클릭이 팬이 아니라 액션이고, 더블클릭 이동도
  꺼진다(연타가 창 이동으로 새면 곤란하다). `Esc` 로 해제되고, 7초 동안 안 쓰면
  저절로 꺼진다(`GESTURE_IDLE_MS`).
  계속 때리면 😵 → 😣 → 😠 → 😡 → 👿 → **😈**, 계속 쓰다듬으면
  😊 → 😄 → 🥰 → 😍 → 🤩 → **😇**. 단계당 5회(`MOOD_STAGE_HITS`)이고,
  반대 행동을 하면 상대쪽 누계는 0 이 된다. 25초 아무것도 안 하면 풀린다.
  때리면 잠깐 바쁘게 움직이지만 **연출일 뿐이다** — 이 앱은 트랜스크립트를 읽기만
  하고 돌아가는 세션에 뭘 보낼 통로가 없다.
- **캐릭터 더블클릭(제스처를 안 켠 상태) = 그 세션을 연 창으로 이동.** 트랜스크립트에 창 핸들도 PID 도
  없어서 창 '제목' 으로 찾는다 — VSCode 로 연 세션은 `Code` 창을 우선한다.
  기본은 **창 단위**지만 두 곳은 **그 안까지** 간다.
  Windows Terminal 은 탭이 UI 자동화 트리에 있고 탭 이름이 세션 제목이라 그 탭을
  고른다. Claude 데스크톱 앱은 사이드바의 대화 목록이 렌더러 창의 접근성 트리에
  버튼으로 있어 그 대화를 누른다. VSCode 의 편집기 탭은 OS 탭이 아니라 못 간다.

  데스크톱 앱 쪽에는 함정이 셋 있었다(전부 실측으로 잡았다).
    - 내용은 최상위 창이 아니라 자식 `Chrome_RenderWidgetHostHWND` 트리에 있다.
    - 그 렌더러 창이 **여럿**이고 첫 번째는 비어 있다 — 내용 있는 것을 골라야 한다.
    - Chromium 은 접근성 클라이언트를 보고서야 트리를 만든다 — 첫 조회가 비면 다시 본다.
    - 사이드바 이름이 세션 제목과 다를 수 있다(`…검색` vs `…찾기`). 끝 단어를
      하나씩 떼며 맞춘다.
  제목에 프로젝트 이름이 안 들어가는 창(예: 홈 디렉터리 세션)은 못 찾는다.
  빈 곳을 더블클릭하면 예전처럼 카메라가 초기화된다.

## 쓸모 있는 쪽

- **응답 대기 알림.** 세션이 답을 마쳐 내 차례가 되는 순간 Windows 알림이 뜬다.
  누르면 그 세션 창으로 바로 간다. 트레이 툴팁에도 대기 인원이 붙는다.
  앱을 켜자마자 기존 대기 세션으로 알림이 쏟아지지 않게 첫 payload 는 건너뛴다.
- **파일 충돌 경고.** 두 세션이 10분 안에 같은 파일을 고쳤으면 두 캐릭터를
  붉은 점선으로 잇고 ⚠️ 를 띄운다. 여러 세션을 같은 저장소에 돌릴 때 나는
  덮어쓰기 사고를 터지기 전에 본다. 읽기는 세지 않고 Edit/Write/NotebookEdit 만
  센다. 같은 세션의 서브에이전트끼리는 충돌로 보지 않는다.
- **오늘 쓴 토큰.** 한국 시간 자정 기준으로 오늘치만 센다 — 트랜스크립트 시각은
  UTC 라 그대로 자르면 오전 9시에 날이 바뀐다(`kst_day`). 자정을 넘기면 0 부터
  다시 센다. 세션별 오늘치/누적은 호버 툴팁에.
- **사용량 막대.** 하단 가운데 한 줄에 5시간·7일 한도, 초기화까지 남은 시간,
  오늘 쓴 토큰. 창 폭에 따라 같이 줄어든다(0.6배까지). 못 받으면 숨기지 않고
  이유를 적는다(토큰 없음 / 로그인 만료 / 연결 실패) — 조용히 비면 앱 탓인지
  로그인 탓인지 가릴 수가 없다.
- 프로젝트 이름은 트랜스크립트의 `cwd` 에서 폴더 이름을 뽑아 쓴다. 슬러그
  (`-C--Users-kim-...`)는 경로 구분자와 이름 속 하이픈이 똑같이 `-` 로 뭉개져
  있어 복원할 수 없다 — 창 찾기 검색어도 이 `cwd` 를 쓴다.
  `/usage` 가 부르는 자리를 그대로 부른다(`app/src/usage.js` — 사용자가 먼저 만든
  claude-usage 앱에서 그대로 가져왔다). 5분에 한 번만 묻는다. 데스크톱 앱에서만
  나온다 — 브라우저로 열면 값을 받을 통로가 없어 상자가 안 보인다.

옛 `win-alert` 훅과는 겹친다. 이 앱이 대신할 수 있는 것은 다음과 같다.

    Stop                  턴 종료 -> '응답 대기' 알림으로 대체됨
    PreToolUse(질문/플랜)   AskUserQuestion·ExitPlanMode 는 트랜스크립트에 남아
                          이 앱이 직접 알린다
    Notification          위 둘과 겹치는 자리
    PermissionRequest     **대체 불가** — 권한 요청은 트랜스크립트에 안 남는다.
                          이 앱은 '멈춤?'(턴이 안 끝났는데 조용함)으로 추정만 한다.

훅을 껐다가 되돌리려면 `~/.claude/hooks/win-alert-restore.sh` 를 실행한다 —
끈 설정을 `win-alert-hooks.disabled.json` 에 통째로 보관해 둔다. 스크립트 파일은
지우지 않는다.

## 남에게 넘기기

앱이 서버를 직접 띄우므로 저장소 경로를 몰라도 된다. 넘기는 방법이 둘이다.

**설치 파일 하나 (추천).** `app/` 에서 `npm run dist` → `app/dist/` 에
`ClaudeTown Setup 1.0.0.exe`(95MB) 가 나온다. 받는 사람은 그거 하나만 더블클릭하면
설치되고 시작 메뉴·바탕화면에 아이콘이 생긴다. 프로세스 이름도 `ClaudeTown` 이라
작업표시줄에 Electron 이 아니라 제 이름으로 잡힌다.

빌드는 Windows 쪽에서 돌려야 한다 — WSL 경로(`\\wsl.localhost\...`)에서는
electron 이 제대로 안 뜬다. 저장소를 Windows 폴더에 복사해 거기서 `npm install`
후 빌드하면 된다.

**압축 폴더.** 빌드 도구 없이 지금 것을 그대로 넘길 때.
`node app/tools/make-portable.js <출력폴더>` 로 만든다 — 앱과 electron 바이너리에
더해 `ClaudeTown.vbs`(더블클릭 실행), `시작메뉴에 등록.bat`, `읽어보기.txt` 가
같이 들어간다. 경로를 박지 않아서 어디에 풀어도 동작한다.

서버를 어디서 띄울지는 앱이 정한다 — **가장 최근에 쓴 기록이 있는 쪽**이다.

    mac / linux        이 컴퓨터에서 python3 로 바로
    windows + 네이티브  이 컴퓨터에서 py -3 / python 으로
    windows + WSL      wsl.exe 로 WSL 안에서 (앱 경로를 wslpath 로 변환)

한쪽에 파이썬이 없으면 다음 후보로 넘어간다. 필요한 건 **파이썬 3 하나**뿐이고,
그것도 Claude Code 를 쓰는 쪽에만 있으면 된다.

세션 기록은 **한쪽에만 있지 않다**. 같은 컴퓨터에서도
`Claude Code(WSL 터미널)` 는 WSL 홈에, `Claude 데스크톱 앱`·`VSCode(Windows)` 는
Windows 홈에 갈려 들어간다. 앱이 양쪽을 다 서버에 넘긴다(`CLAUDETOWN_ROOTS`,
`os.pathsep` 로 여러 개. 없는 경로는 조용히 건너뛴다).

세션을 열어준 곳으로 이동할 때도 진입점을 본다 — `claude-vscode` 는 `Code` 창,
`claude-desktop` 은 Claude 앱 창(프로세스 이름 `claude`), 그 외에는 세션 제목이
걸린 터미널 창.

*아직 확인 못 한 것*: 맥에서의 동작. 창 이동은 AppleScript 로 짰지만 실기기가
없어 확인하지 못했고, 손쉬운 사용 권한이 없으면 앱만 앞으로 부르는 데서 그친다.
토큰도 맥은 키체인에서 읽게 해 뒀는데 마찬가지로 미확인이다.

타일시트는 `assets/` 에 이미 들어 있어 따로 받을 필요는 없다. 최신판으로
다시 받거나 갱신하고 싶을 때만 `./fetch_assets.sh` 를 실행한다.
